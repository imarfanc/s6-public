# Apps

How to write an app. Repo invariants for agents live in `AGENTS.md`.

One folder per app. A folder becomes an app the moment it contains an `app.yaml`; there is nothing
to register by hand — `backends/routes/apps.ts` walks this tree and serves the result as
`GET /api/apps`. Frontend files live in `web/`, optional backends in `server/`, seed data in
`data/`. Code used by more than one app lives in `_shared/`.

On Val Town that walk is expensive: there is no filesystem there, so every folder listing and every
marker is an HTTP round trip. `apps/_manifest.json` is that walk precomputed, generated by
`deno task manifest` and committed, exactly as the icon sprite is. **The folders remain the source
of truth** — locally the manifest is never read, and `deno task check` fails when it disagrees with
what is on disk.

## Adding an app

1. Make a folder under `apps/`.
2. Copy `_templates/app.template.yaml` into it as `app.yaml` and fill it in.
3. Put an `index.html` in `web/`.
4. Run `deno task check` and do what it names (`deno task manifest`, `deno task icons`).

`deno task dev` watches `apps/`, so a save is enough to pick the new app up.

Sidebar placement comes from `appspace` and `sections`, not the folder path. A folder at
`apps/26.9/todo2/` with `sections: [testing, sqlite]` shows up under **testing / sqlite**. Serving
is the folder path: `/apps/<folder path>/`.

## `app.yaml`

| Field         | Required | Meaning                                                             |
| ------------- | -------- | ------------------------------------------------------------------- |
| `id`          | yes      | `#app=` deep link and Recently opened key. Use the folder name.     |
| `status`      | no       | `active`, `parked`, or `reference`.                                 |
| `name`        | yes      | Sidebar label.                                                      |
| `sort_name`   | no       | Sort key; falls back to `name`.                                     |
| `description` | no       | Shown in search matching.                                           |
| `icon`        | no       | Iconify name such as `lucide:list-checks`.                          |
| `color`       | no       | Hex accent; tints the sidebar while the app is open.                |
| `appspace`    | yes      | Top-level grouping. Each appspace is a separate tree.               |
| `sections`    | no       | Ordered path; each item nests under the previous one.               |
| `tags`        | no       | Extra search terms.                                                 |
| `store`       | no       | Namespace for saved data and tables. See below.                     |
| `db`          | no       | Schema generation — `v1`, `v2`. See below.                          |
| `entry`       | no       | File served for the app. Defaults to `index.html`.                  |
| `backend`     | no       | Repo path to `route.ts`. Must be listed in the router's `HANDLERS`. |
| `children`    | no       | Sub-pages in `web/`, listed as rows under the app.                  |
| `aliases`     | no       | Retired `#app=` ids that still resolve to this app.                 |

`updated:` is not a field. Discovery fills it from the last commit touching the app folder, so
`deno task manifest` refreshes the dates the "recently updated" view sorts by — `deno task check`
ignores them, because a commit moves them with nobody editing a file. An app shows as undated
wherever there is no repository to ask. `schema_version` and any other undeclared key fail the
check.

## `children`

A flat list of files in `web/`, each an entry point in its own right:

```yaml
children:
  - editor.html
```

Each becomes an indented row under the app, labelled with the filename minus its extension, and
opens at `/apps/<folder path>/<file>` — the same way `entry` opens. A child is an ordinary page, not
a parameter. Deep links carry the selection as `#app=<id>&child=<file>`. The check fails if the file
is missing.

## `aliases`

When renaming an app, move the old `id:` here rather than deleting it. `#app=<old>` and Recently
opened still find the app; new links write the live `id:`. An alias that collides with any live `id`
or another alias fails the check.

## `store`

An app that needs to save something imports `/shared/store.js` and calls it:

```js
import { store } from "/shared/store.js";

const data = store();
await data.put("scene", { elements: [] });
const saved = await data.get("scene"); // null until something is written
```

There is no route to add and no backend file to write. `store.js` derives the app from
`location.pathname`, and `/api/data/` is one handler shared by every app. Values are capped at 10 MB
and reachable only through the same session cookie as the rest of the site.

`get`/`put` are JSON. For anything else, give the key an extension and use `getText`/`putText`:

```js
await data.putText("rows.csv", "a,b\n1,2\n");
```

The extension decides both how the value is served and how it is checked on the way in. A body that
does not parse is rejected with the parser's own message, so a truncated write fails at the call
rather than surfacing as a broken app later:

| Extension                        | Served as          | Checked with                                                  |
| -------------------------------- | ------------------ | ------------------------------------------------------------- |
| `.json`, none, anything unlisted | `application/json` | `JSON.parse`                                                  |
| `.yaml`, `.yml`                  | `text/yaml`        | `@std/yaml`                                                   |
| `.csv`                           | `text/csv`         | `@std/csv`, holding every row to the first row's column count |
| `.md`                            | `text/markdown`    | nothing — any text is valid                                   |
| `.txt`                           | `text/plain`       | nothing — any text is valid                                   |

These are real parsers, not `shared/app-yaml.ts`. That module reads a deliberately tiny YAML subset
because `app.yaml` is hand-written and stays small; this route sees whatever an app sends, where a
subset would reject valid documents. They are loaded from pinned URLs rather than bare specifiers —
see the remote-imports note in `backends/README.md`.

`store:` names the folder that data lands in. It is deliberately not the folder path: `id:` is the
deep link and should outlive a rename, and saved data should too. Leave `store:` out and it falls
back to `id`.

Storage is Val Town's blob store in production and `_other/data/<dbPrefix>/blob/` locally, decided
in `backends/shared/blob.ts`. Nothing about that reaches the app.

## `db`

`store:` saves a document; `db:` saves rows. An app that wants tables sets `db: v1` and adds two
files in `web/` — `schema.sql` and `queries.sql`, both templated in `_templates/`:

```sql
-- schema.sql
CREATE TABLE IF NOT EXISTS {todos} (id INTEGER PRIMARY KEY AUTOINCREMENT, text TEXT NOT NULL);

-- queries.sql
-- name: listTodos
SELECT id, text FROM {todos} ORDER BY id DESC;
```

```js
import { db } from "/shared/db.js";

const todos = db();
await todos.run("addTodo", ["milk"]);
const rows = await todos.rows("listTodos");
```

As with `store.js` there is no route to add and no backend file to write. Three things are worth
knowing before writing the first query:

- **The browser sends a query name, never SQL.** `run` names a block in `queries.sql` and the server
  runs the repository's copy of it. One endpoint can therefore be shared by every app without the
  session cookie being all that stands between a browser and `DROP TABLE`. Adding a query means
  editing the file.
- **`{todos}` is a token, not a table name.** Every app shares one SQLite database, so the server
  expands it to `<store>_<generation>_todos`. Declare every table in `schema.sql`; a token in
  `queries.sql` that is not declared there is an error at load. Index names need a token too —
  `CREATE INDEX IF NOT EXISTS {todos}_done ON {todos} (done)`.
- **`schema.sql` and `queries.sql` are read once per process.** `deno task dev` watches `apps/`, so
  a save is enough.

Changing a column means bumping `db:` to `v2`: the new generation gets empty tables and an optional
`migrate.sql` copies the old rows across, naming the previous generation's table as `{prev.todos}`.
It runs once and is recorded in `<dbPrefix>_migrations`. Adding a nullable column needs no bump —
put an `ALTER TABLE ... ADD COLUMN` below the `CREATE TABLE` in `schema.sql`.

The database is Val Town's SQLite in production and `_other/data/<dbPrefix>/sqlite.db` locally,
decided in `backends/shared/sqlite.ts`. Nothing about that reaches the app.

## Sections

`sections-metadata.yaml` gives a section its icon, colour, and sort order. A section name used by an
app but missing from that file — or defined there and unused — fails the check. An appspace name
used by an app but missing from the `appspaces:` list also fails. Optional `password_env:` on an
appspace entry names the environment variable that holds that appspace's password; omit it to leave
the appspace public.

## What is checked

Discovery throws if `id`, `name`, or `appspace` is missing. `deno task check` runs
`_other/tools/build-manifest.ts --check`, which fails on a stale manifest, a duplicate `id` or
alias, an unknown field, a bad `status`/`color`/`store`/`db`, a missing `backend:` or `children:`
file, a `backend:` not listed in `HANDLERS`, a section or appspace drift, a bad `password_env`, or
an Iconify name missing from the sprite. A typo should fail the check, not the sidebar.

## Reserved names

Folders starting with `_` or `.` are skipped by discovery, which is why `_templates/` is not an app,
and why `_shared/` can hold code that apps import without becoming one itself. `_manifest.json` is
generated; edit the `app.yaml` files and rerun `deno task manifest` rather than the file.
